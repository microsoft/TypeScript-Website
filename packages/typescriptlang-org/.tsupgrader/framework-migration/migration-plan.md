## Implementation rules

1. No Astro-specific source, configuration, dependencies, scripts, or output may be added to the Gatsby package.
2. The target may not import `packages/typescriptlang-org` source. Shared code must be extracted deliberately into an explicit framework-independent package/location.
3. Existing public URLs, locale behavior, hosting model, generated content, metadata and browser behavior are preserved unless the user explicitly approves a difference.
4. Source-declared exact route counts are authoritative where stale Gatsby output is incomplete; output parity must explain all differences.
5. Route families are migrated and validated as complete families, not representative pages.
6. React is retained only for interactive islands or a risk-reducing intermediate conversion, with no Gatsby APIs or compatibility shims.
7. The source remains independently buildable until preview approval. Cutover and deletion begin only after explicit user approval.
8. Every failed validation reopens or creates a plan item. Evidence is retained under `evidence/`.
